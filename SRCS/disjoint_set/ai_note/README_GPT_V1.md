# Union-Find

## 1. Union-Find의 기본정의와 개념을 학습.

## 2. Union-Set의 기본단위 구축. Union-Set의 가장 기본적인 연산은 원소의 소속을 확인하는 `Find`, 서로 다른 집합을 하나로 합치는 `Union`으로 나뉨. 실제 집합의 상태를 저장하는 방식은 별도의 `Store`로 분리.
## 따라서 가장 기본적인 추상클래스를 작성하고, 해당 추상클래스를 구현할 때 따라야 할 규칙을 타입검사 수준에서 확인할 수 있도록 `Protocol`을 작성.
## 최상위 계층에는 `AbstractDisjointSet`이라는 상속 기반 추상클래스와, 해당 인터페이스의 최소 기능을 구조적으로 검사할 수 있는 `DisjointSet` `Protocol`을 작성.
## 각각 최소 필요한 함수 `FIND`, `UNION`을 의미 있게 명시함. 추가적으로 `AbstractDisjointSet`에서는 구현에 필요한 `Storage`를 생성 시 전달받도록 하여, 하위 구현체가 필요한 저장 구조를 반드시 갖도록 구성.

## 3. 구체적인 학습에서 `Generic T`, `K`를 사용함. `T`는 실제 데이터 원소의 타입이며, `K`는 각 원소가 속한 그룹의 동일성을 나타내는 Group ID 타입으로 정의.
## `T`, `K`는 구현에 따라 다른 타입을 사용할 수 있으며, 기본적인 Group 기반 구현에서는 `K`를 `int`와 같은 단순한 타입으로 사용할 수 있음.
## `K`의 equality를 기본적으로 사용할 수 없는 복합 구조나 별도의 동일성 기준이 필요한 경우를 대비하여, `Identity`를 외부에서 전달받을 수 있도록 구성. `Identity`는 두 개의 `K`를 비교하여 동일 그룹인지 `bool`로 반환하는 `Callable` 계약으로 정의.

## 4. 다음 단계에서는 가장 기본적인 Union-Set을 `Find`, `Union`, `Storage`의 세 축으로 구성하고, 그룹 동일성 판단에 필요한 `Identity`를 추가적인 정책으로 둠.
## 가장 추상화된 기본 구현에서 `Find`는 해당 원소가 속한 그룹의 `K`값을 반환하므로, 내부에서는 `K`가 구체적으로 어떤 자료형인지 알 필요가 없도록 구성.
## `Union`은 `Find`를 통해 두 원소의 그룹 `K`값을 가져온 후 두 그룹이 동일한지 확인하고, 서로 다른 경우 `Store`에 두 그룹의 병합을 요청하는 구조로 구현.
## 이때 그룹 동일성은 외부에서 전달받은 `Identity`를 통해 판단하며, 기본적인 타입에서는 `lambda a, b: a == b`를 사용할 수 있고, 특수한 자료형에서는 별도의 `Identity` 구현을 전달할 수 있도록 구성.
## `Identity`가 `None`인 경우 생성자 인자의 기본값으로 callable을 직접 지정하기보다, 생성자 내부에서 `None`을 검사한 후 기본 equality 함수를 명시적으로 초기화하여 이후 구현부에서는 항상 유효한 `Identity`가 존재하도록 구성. 이는 타입 안정성과 내부 상태의 명확성을 유지하기 위한 설계로 판단.
