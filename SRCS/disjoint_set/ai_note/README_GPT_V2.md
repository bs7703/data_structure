# Union-Find

## 1. Union-Find의 기본정의와 개념을 학습.

## 2. Union-Set의 기본단위 구축. Union-Set의 가장 기본단위는
## 값에 해당하는 저장체(Storage)와 기능에 해당하는 서로 다른 집합을 합치는 연산(Union), 원소의 소속을 찾는 연산(Find)으로 나뉨.
## 따라서 가장 기본적인 단위의 추상클래스를 작성하고, 해당 추상클래스를 구현할 때 따라야 할 규칙을 타입검사 수준에서 확인할 수 있도록 Protocol을 작성.
## 최상위 계층에 AbstractDisjointSet이라는 상속 기반 추상클래스와, 해당 인터페이스의 최소 규격을 구조적으로 확인할 수 있는 Protocol인 DisjointSet을 작성.
## 각각 최소 필요한 함수 FIND, UNION을 의미 있게 명시함. 추가적으로 AbstractDisjointSet에서는 Storage의 필요성과 Storage가 만족해야 할 Protocol 타입을 명시적으로 지정하여 구현.

## 3. Generic T와 K를 사용해 두 개의 추상 타입을 정의함.
## 이때 T는 실제 데이터 원소의 타입을, K는 각 원소가 속한 Group의 identity를 나타내는 타입으로 정의함.
## T와 K는 실제 구현에 따라 타입이 변할 수 있으며, 일반적인 경우 K를 기본 자료형으로 사용할 수 있음. 두 K의 동일성은 일반적인 equality 연산으로 판단할 수 있음.
## 하지만 기본 equality만으로 원하는 동일성 기준을 표현하기 어려운 복합 구조나 특수한 경우를 대비하여 Identity라는 동일성 판단 기준을 외부에서 함수로 받아 초기화할 수 있도록 구현.
## 따라서 Identity를 Callable을 이용해 K 두 개를 입력받아 동일 그룹 여부를 bool로 반환하는 계약으로 규정.
## 기본적인 타입의 경우에는 생성자 내부에서 기본 equality인 `lambda a, b: a == b`를 사용하고, 특수한 경우에는 외부에서 별도의 Identity를 전달하는 방식으로 구현.

## 4. 다음 단계에서는 Union-Set을 기능에 해당하는 두 축 Union, Find와 상태를 표현하는 Storage로 구성함.
## 기본적인 Union-Set은 가장 추상화된 단계에서의 구현이므로
## Find → 해당 원소가 속한 Group을 식별하는 K값 또는 그에 대응하는 대표값을 가져오는 연산으로 정의하여, K가 어떤 구체적인 자료형으로 구현되는지는 상위 추상 계층에서 알 필요가 없도록 함.
## Union → Find를 통해 두 원소의 K값을 가져온 후 Identity를 통해 두 그룹이 동일한지 비교하고, 서로 다른 경우 두 그룹을 하나로 통합하도록 Store에 요청하는 추상 구조로 구현.
## 생성자 → Group의 정체성을 구분하기 위한 Identity와 상태를 저장하기 위한 Storage를 주입받도록 구성.
## 이때 Identity가 비어 있는 경우 생성자 인자의 기본값으로 함수를 직접 지정하기보다, 생성자 내부에서 None 여부를 검사한 후 기본 equality 함수를 명시적으로 할당하여 이후 구현부에서는 항상 유효한 Identity가 존재하도록 구성.
## 또한 Storage는 실제 Find, Union 구현 단계에서 필요한 기능을 만족하는 Protocol을 통해 자격을 제한하고, Union-Set의 구체적인 구현 방식과 독립적으로 교체할 수 있도록 구성.
